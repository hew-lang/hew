# Hew 0.9.0

Hew 0.9 adds deferred values, configurable restart delays and asynchronous
native host calls. It continues language edition 2026.

## Initialize a value when it is needed

`std.lazy` keeps an initializer until the first call to `value()`:

```hew,no_run
import std.lazy;

fn main() {
    var greeting = lazy.new(|| {
        println("initializing");
        "hello"
    });
    println("created");
    assert(greeting.value() == "hello");
    assert(greeting.value() == "hello");
}
```

This prints `created` before `initializing`, and initializes only once. Each
read returns an ordinary `Clone` of the cached value. Plain value mutations
leave the cache unchanged; explicitly shared handles keep their usual sharing.
The initializer may suspend. Ordinary errors
returned as `Result.Err` are cached as values. A fault or cancellation leaves
initialization terminal; later demand faults instead of retrying.

The lazy owner releases an unused initializer's captures or its cached value
when it leaves scope. See the [configuration example](../../examples/lazy_values.hew).

## Space out supervisor restarts

```hew
import std.restart;

actor Worker {
    receive fn fail() { panic("worker failed"); }
}

supervisor Team {
    strategy: one_for_one;
    intensity: 3 within 10s;
    backoff: restart.exponential(initial: 100ms, maximum: 5s);
    child worker: Worker;
}

fn main() {
    let team = spawn Team;
    let _ = team.worker.fail();
    restarted(team.worker);
    stop(team);
    stopped(team);
}
```

The first crash waits `initial`; repeated crashes double the delay up to
`maximum`. Each child role tracks its own delay, including pool members and
nested supervisor children. After a replacement runs for a healthy restart
window, its next crash uses `initial` again. Waiting for a replacement does
not count as healthy execution. Restart intensity continues to limit failures
independently.

The policy expression runs once when constructing its supervisor. Existing
strategies, stable role identity and crash hooks continue to apply. Leaving out
`backoff` keeps the previous restart behaviour. Native and sandbox execution use
the same selected policy.

## Pass streams to generic iterator consumers

`Stream<T>` now implements `Iterator<Item = T>`. A function bounded by that
trait can consume a stream directly, including streams from `std.stream.pipe`.
For a pipe, closing or finishing its last sink ends iteration after buffered
values are drained.
The [generic iterator example](../../tests/core-acceptance/cases/stream-generic-iterator.hew)
shows a consumer shared through an ordinary trait bound.

## Drive native calls from a host event loop

Use `--export-c-async SOURCE=SYMBOL` with `hew build --emit-obj` to generate a
typed call owner and `SYMBOL_start`, `_poll`, `_cancel`, `_result` and `_release`.
Existing synchronous `--export-c` signatures stay unchanged. Both selectors
use ordinary checked public Hew functions.

Poll returns pending without waiting. A retained wake callback schedules the
next poll on the host thread. Cancellation requests cleanup; keep polling until
ready, take the result or owned error once, then release the call. A terminal
success wins late cancellation. Early result transfer or release refuses with
`HEW_INVALID_STATE` and leaves the owner untouched.

The [asyncio order copier](../../examples/embedding/asyncio_orders.py) runs the
supplied-directory actor component from Python's real event loop. It drains
native cleanup before propagating `CancelledError`. The
[host guide](../../tests/host/README.md#drive-calls-from-an-event-loop) includes
the generated C lifecycle and complete build/run commands. This experimental
native interface requires matching compiler/runtime builds and the existing
process runtime.

The [migration guide](../migrations/v0.9.0.md) covers adopting these surfaces.
