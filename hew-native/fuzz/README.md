# Compiled Hew fuzz testing

This target compiles a small Hew adapter with the exact compiler and `libhew.a`
being tested, then links it into a native C libFuzzer harness. It exercises
standard-library code, generated ownership and cleanup, the checked C host
boundary, and ASan-instrumented LLVM output in one process. The C harness keeps
`libhew.a` as the sole Rust runtime provider.

`fuzz_stdlib_text` covers the pure-Hew Base64, hex, CSV and binary parsers plus
the public Hew wrappers for JSON, YAML, TOML, XML, CBOR and MessagePack. Ordinary
parse errors are data. A logical fault, sanitizer report, ownership failure or a
serializer refusing its own output is a finding.

`Fuzz.toml` is the service discovery manifest. The continuous fuzz service
builds the matching compiler and `libhew.a`, compiles the Hew adapter with
address instrumentation, applies libFuzzer coverage to its emitted LLVM IR,
and links the native harness with `-fsanitize=fuzzer,address`.

The checked-in seeds are generated by `seeds/make-seeds.py`. They include
valid binary CBOR and MessagePack documents so both byte-preserving paths are
reached before mutation begins. Run `python3 seeds/make-seeds.py --check` to
verify the corpus.
