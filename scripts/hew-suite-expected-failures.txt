# hew-suite-expected-failures.txt
#
# Known failing tests in tests/hew/.
# The ratchet (scripts/hew-suite-ratchet.sh) enforces:
#   - Every test listed here MUST fail (unexpected pass = gate failure).
#   - Every test NOT listed here MUST pass (unexpected failure = gate failure).
#
# This is a tracked-failure list, not a waiver. An entry earns its place by
# naming the defect class that keeps it red; nothing lands here to make the
# gate green. Remove an entry the moment its class is fixed — the ratchet
# fails on an unexpected pass precisely so a fix cannot go unnoticed.
#
# Entries marked NEWLY-SURFACED are not inherited, and they are FALSE
# rejections — the first thing to fix off this branch. The extern-contract
# comparison rejects a symbol whose two declarations name different nominal
# owners, and in a unit that imports both std::net::http and its http_client
# submodule it sees a conflict that no source states:
#
#   - hew_http_request_hew and the hew_http_response_* family are declared
#     exactly once, in std/net/http/http_client.hew. The checker registers
#     that one declaration under two owners (std.net.http and
#     std.net.http.http_client) and reports the module against itself; the
#     "first declaration" spans point into unrelated comments in http.hew,
#     which declares none of those symbols.
#   - hew_sink_is_valid really is declared twice (std/stream.hew and
#     std/net/http/http.hew), but both name the same type. One spells the
#     owner `stream`, the other `std.stream`, and canonical_nominal_name
#     resolves the partially-qualified spelling only through an import
#     binding that http.hew does not have.
#
# Both are owner-identity gaps in extern registration, not contract defects.
#
# Format: <test_function_name>  # <class>: <root cause>
#
# Total: 84 unique failing test function names.
