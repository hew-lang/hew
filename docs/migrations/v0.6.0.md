# Migrating to Hew v0.6.0

## Native cutover surface

Ordinary calls wait, including void actor handlers. Use `fork` for concurrency
and `await` on `Task<T>` or `Vec<Task<T>>`, producing `T` or `Vec<T>`.
A scope produces a value; structured fault/cancellation recovery runs after
child cleanup, while an ordinary Err remains a value. Use mailbox views for
submission and policy views for completion-call admission. The former send,
join, actor-await and timeout-combinator spellings are retired, not aliases.

Use semicolons for bodyless declaration members and commas for values and lists.
Members with their own `{ }` body end at that brace. Actor state fields start
with `let` or `var`. Run `hew fmt --migrate` to update old punctuation before
checking or building a project. Use `type` for records, dotted module paths,
immutable `let` and mutable `var`. Resource cleanup is `close(consume self)`
returning unit; handle fallible finish or commit separately. JSON values clean
up automatically and need neither free nor close.

Some intended contracts still await implementation, notably typed rejected
requests and supervisor close forms. See the [language guide](../hew-language-guide.md)
for those limits. The API inventory below also contains earlier migration
history; it is not evidence that every listed destination has landed.

v0.6.0 freezes the language surface before edition 2026 stabilizes. Breaking a
name is cheap at today's audience and unaffordable later, so the renames and
deletions that were going to happen eventually happen now, once.

This file is the only place the retired spellings are written down. The
specification and the guide describe the surface as it is; a reader who meets
an old name in someone else's code finds it here.

## Keyed construction

Parentheses hold positional arguments and braces hold keyed ones. A spawn, a
supervisor child and a transition head bind by name, so they now use braces:

| Retired                                      | Current                                         |
| -------------------------------------------- | ----------------------------------------------- |
| `spawn Counter(count: 0)`                    | `spawn Counter { count: 0 }`                    |
| `spawn Store()`                              | `spawn Store`                                   |
| `child w: Worker(id: 1) restart: transient;` | `child w: Worker { id: 1 } restart: transient;` |
| `on Open(by): Shut => Ajar { by: by }`       | `on Open { by }: Shut => Ajar { by: by }`       |

`hew fmt --migrate` rewrites each site. `spawn Store {}` and a `..base` in a
spawn are refused. Calls stay positional with optional named arguments: a bare
name in a call never binds by name.

## Errors and fallibility

Every fallible standard-library function returns `Result<T, E>` with
`E: Error`, and the bare name carries it (HEW-SPEC-2026 §3.10.3). The `try_`
prefix is gone, along with the panicking twin that used to sit beside it.

| Retired                                                                                                                                                 | Current                                                 | Notes                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `fs.try_read(p)`                                                                                                                                        | `fs.read(p)`                                            | Returns `Result<string, IoError>`                                                     |
| `fs.try_write`, `try_append`, `try_delete`, `try_mkdir`, `try_mkdir_all`, `try_list_dir`, `try_rename`, `try_copy`, `try_read_bytes`, `try_write_bytes` | the same name without `try_`                            | Same shape throughout `std.fs`                                                        |
| `net.connect`, `net.connect_timeout`                                                                                                                    | unchanged names                                         | Both constructors now return `Result<Connection, NetError>`                           |
| `process.run`, `try_run_argv`, `try_start`, `try_start_argv`                                                                                            | `process.run`, `run_argv`, `start`, `start_argv`        | The bare names now carry `Result<T, ProcessError>`                                    |
| `tls.write`                                                                                                                                             | `tls.write`                                             |                                                                                       |
| `fs.read(p)` returning a bare `string`                                                                                                                  | `fs.read(p)?`                                           | The former bare form silently returned an empty value on failure                      |
| `os.env(name)` returning `string`                                                                                                                       | `os.env(name)` returning `Option<string>`               | The unset case used to return a zero-length string that did not compare equal to `""` |

| `string.to_int`, `string.to_float` failing with `string`                                                                                                | `fails string.NumberError`                              | `Invalid(text)` or `OutOfRange(text)`                                                 |
| `crypto.random_bytes` failing with `string`                                                                                                             | `fails crypto.RandomError`                              |                                                                                       |
| `toml.stringify` failing with `string`                                                                                                                  | `fails toml.EncodeError`                                |                                                                                       |

| `datetime.format`, `datetime.parse` failing with `string`                                                                                               | `fails datetime.DateTimeError`                          | `Format(reason)` or `Parse(reason)`                                                   |

| `unicode.codepoint_at`, `unicode.rune_len` failing with `string`                                                                                        | `fails unicode.UnicodeError`                            | `IndexOutOfBounds(i)` or `InvalidRune(cp)`                                            |

### Failure edges

A callable fails through its declared edge, `fails E`, and nowhere else
(HEW-SPEC-2026 §2.2.1). `?` on a `Result` and `return error` need that edge;
a `-> Result<T, E>` return is a value its body builds, and its tail is no
longer wrapped. `hew fmt --migrate` converts every `-> Result` callable that
uses `?` or `return error`, or relied on the wrapped tail, and leaves value
returns as written. A `receive fn` keeps its reply as a `Result`: its `?`
becomes an explicit `match` returning `.Err(error)`, preserving the caller's
reply envelope. To put failures in `ActorError.Failed`, declare the handler's
`fails E` edge explicitly.

| Retired                                                                   | Current                                          | Notes                                                                              |
| ------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `fn f() -> Result<T, E> { let x = g()?; .Ok(x) }`                         | `fn f() -> T fails E { let x = g()?; x }`        | `?` and `return error` in a value body are `E_NO_FAILURE_EDGE`                     |
| `-> Result<(), E>` with `.Ok(())` at the end                              | `fails E`, falling off the end                   |                                                                                    |
| `return .Err(e)` or a tail `.Err(e)` in a failing body                    | `return error e`                                 |                                                                                    |
| a tail `x` wrapped into `Ok(x)` under `-> Result<T, E>`                   | `-> T fails E`, or build `.Ok(x)` yourself       | A success value where a value return expects its `Result` is a mismatch            |
| `\|t\| { let v = g(t)?; .Ok(v) }` passed where a `Result` is expected     | `\|t\| { let v = g(t)?; v }`                     | A closure that uses `?` or `return error` fails through its own edge               |
| `receive fn f() -> Result<T, E>` using `?`                                | keep `-> Result<T, E>`; replace `?` with `match` | Callers keep `.Ok(.Err(e))`; declaring `fails E` is an explicit author choice      |
| `impl Display for X` restating each variant, beside `impl Error for X {}` | `impl Error for X {}`                            | `Error` supplies the variant-name-then-payload text when `X` declares no `Display` |
| `impl From<Low> for High { fn from(v: Low) -> High { .Wrapped(v) } }`     | (delete it)                                      | A failure edge wraps `Low` in the one variant that carries it alone                |
| `gen fn f() -> Y fails E` refused                                         | yields `Result<Y, E>` items                      | The consumer writes `let y = item?;`                                               |

## Pipes

`std.channel`, the duplex pair and the socket read/write methods fold into
one pipe family in `std.stream`: `Stream<T>` reads, `Sink<T>` writes, and
the same two types name an in-memory pipe, a file and a split socket.

| Retired                                                        | Current                                                        | Notes                                                            |
| -------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------- |
| `channel.new(n)` → `(Sender<T>, Receiver<T>)`                  | `stream.pipe(n)` → `Result<(Sink<T>, Stream<T>), string>`      | Element type from use or the binding annotation                  |
| `stream.pipe(n)` (text) and `stream.bytes_pipe(n)`             | `stream.pipe(n)` for every element type                        |                                                                  |
| `tx.send(v)` returning nothing, `sink.write(v)`                | `sink.send(v)` → `Result<(), SendError>`                       | Discarding the result is `E_RESULT_DROPPED`                      |
| `sink.try_write_*`                                             | `sink.try_send(v)`                                             | Adds `Err(SendError.Full)`                                       |
| `hew_sink_shutdown(sink)` extern                               | `sink.finish()`                                                | Keeps the handle; on a socket sends FIN                          |
| `duplex_pair`, `send_half`, `recv_half`                        | two `stream.pipe` pairs, or `conn.split()`                     |                                                                  |
| `conn.into_stream_sink()`                                      | `conn.split()`                                                 |                                                                  |
| `conn.read()`, `conn.read_string()`, `conn.try_read*`          | `conn.recv()` → `Option<bytes>`                                | A transport failure traps; `None` is end of data                 |
| `conn.write(b)`, `conn.write_string(s)`, `conn.send_string(s)` | `conn.send(b)` → `Result<(), SendError>`                       |                                                                  |
| `stream.from_file(p)` → `Result<Stream<string>, fs.IoError>`   | `stream.open(p)` → `Result<Stream<bytes>, string>`; `.lines()` |                                                                  |
| `stream.to_file(p)`                                            | (deleted)                                                      | Write with `fs.write`, or forward into an HTTP body sink         |
| `Stream.map`, `Stream.filter`                                  | (deleted)                                                      | Transform in the consuming loop                                  |
| `WriteError`, `RecvError`, `CloseError`, `ReadStringError`     | `SendError`                                                    | The one delivery error for sinks and sockets                     |
| `#[wire]` required on a pipe payload                           | (removed)                                                      | Payloads follow the message rule: data, no containers or handles |

A pipe is also a `select` source (`item from rx.recv()` binds `Option<T>`),
and a sink released by a crashing actor faults the pipe so the reader traps
rather than reading a clean end.

Indexing is the one place a failure still traps rather than returning a
`Result`: `v[i]`, `m[k]`, and `Vec.set` out of bounds are program errors, and
`.get()` is the `Option`-returning accessor for the case where a miss is
expected.

`collections/` path.

## One form per operation

| Retired                                                                                     | Current                                                          |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `sort.sort_ints`, `sort_strings`, `sort_floats`                                             | `sort.sort<T: Ord>`                                              |
| `sort.reverse_ints`, `reverse_strings`, `reverse_floats`                                    | `sort.reverse<T>`                                                |
| `assert_eq`, `assert_ne`, `std.testing` and its per-type assertion family                   | `assert(a == b)`, `assert(a != b)`, `assert(condition, message)` |
| the monomorphic helpers in `std.vec`, `std.option`, `std.result`                            | the generic function of the same name                            |
| `random.shuffle`                                                                            | (deleted)                                                        |
| the bare `sqrt`, `abs`, `min`, `max`, `pow`, `floor`, `ceil`, `round`                       | `math.sqrt` and friends, after `import std.math`                 |
| `math.*` and `random.*` with no import                                                      | `import std.math;` / `import std.random;`                        |
| the `string_*` builtin family, `substring`, the free `len`, the four `*_to_string` builtins | methods on `string`, and `Display` for rendering                 |
| the free-function twins in `std.string` and the aliases in `std.fmt`                        | the method of the same name                                      |
| `csv.Table.free`, `semver.Version.free`                                                     | `close()`, or scope-exit drop glue                               |
| `json.Value.free`                                                                           | automatic value cleanup; no explicit release                     |
| the `Closable` trait                                                                        | a `#[resource]` type's `close` method                            |

`assert` reports a failed comparison's operands as `{:?}` renders them, so an
`Option`, a `Result` or a record compares directly: `assert(parsed == expected)`.

`std.math` and `std.random` are ordinary modules now: nothing binds `math` or
`random` without its import, and the math functions have no bare spelling.
`math.log2`, `math.log10`, `math.exp2` and `math.tanh` had no declaration
behind them and are gone with the rest.
