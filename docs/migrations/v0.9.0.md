# Migrating to Hew 0.9

Edition 2026 stays unchanged. Update the compiler and its bundled standard
library together. Packages using these additions should require Hew 0.9.0 or
newer in `hew.toml`.

## Standard-library module paths

Update imports and their default qualifiers together:

| Previous import                  | Current import        | Default qualifier |
| -------------------------------- | --------------------- | ----------------- |
| `std.misc.log`                   | `std.log`             | `log`             |
| `std.misc.uuid`                  | `std.uuid`            | `uuid`            |
| `std.crypto.crypto`              | `std.crypto.hash`     | `hash`            |
| `std.net.http`                   | `std.net.http.server` | `server`          |
| `std.net.http.http_client`       | `std.net.http.client` | `client`          |
| `std.net.http.http_async_client` | `std.net.http.codec`  | `codec`           |
| `std.net.http.http_async_server` | `std.net.http.codec`  | `codec`           |

The pure request/response codec has one module owner. Its ordinary value types
are `codec.Request` and `codec.Response`; replace the `AsyncRequest` and
`AsyncResponse` names. Client and server resources live in their respective
modules. Ordinary suspending calls provide concurrency without an `async`
module-name variant.

## String and collection helpers

Use string methods for conversion and manipulation: `text.to_int()`,
`text.to_float()`, `text.count(needle)`, `text.pad_left(width, '0')`,
`text.pad_right(width, ' ')` and `text.repeat(count)`. The duplicate module-level
string and formatting wrappers are removed. Padding takes one `char`.
Character classification belongs to `char`; use character predicates or a
checked numeric conversion instead of whole-string classification aliases.

Replace the typed vector helper families with `vec.index_of`, `vec.first`,
`vec.last`, `vec.min` and `vec.max`. Their type parameters replace `_i32`, `_i64`,
`_f64` and `_str` suffixes. Empty collections still produce `None`.

## Checked parsing and file queries

`cron.parse` and `Expr.next` now return errors instead of trapping on invalid
input or an unavailable next occurrence; replace `try_parse` and `try_next`
with those names. Handle the result with `?`, `match`, `handle` or `expect`.

`regex.new` returns a checked pattern. Replace `Pattern.matches` with
`Pattern.is_match`. `Pattern.find` returns `Option<string>`, distinguishing no
match from a successful empty match.

Replace `template.render_try` with `template.render_template`, which returns
the render result. The convenience `template.render` also returns errors.
`fs.size` returns a typed I/O error instead of a sentinel size.

## Checked standard input and output

`io.read_line`, `io.read_all`, `io.write` and `io.write_err` now return recoverable
`io.IoError` values. Propagate them with `?`, match the result, or deliberately
choose an application failure with `expect`. A function that propagates these
errors can declare `fails io.IoError`:

```hew,no_run
import std.io;

fn main() fails io.IoError {
    io.write("Name: ")?;
    let name = io.read_line()? ?? "stranger";
    io.write(f"Hello, {name}\n")?;
}
```

Apply `?` before handling the optional line: `io.read_line()? ?? "stranger"`
handles end of input after a successful read. A read failure is a different
outcome. Checked writes wait for the ordered writer to finish, so an output
failure is available to the caller. `print` and `println` keep their existing
queued-output contract.

## Checked HTTP and networking

HTTP client operations return `client.HttpError`, with request, body and header
failure details. `Response.body()` is fallible. `header()` and `content_type()`
return a fallible `Option<string>`: handle the operation error before deciding
what an absent header means. A present empty header remains `Some("")`.
Parenthesize propagation before a member call: `(response.body()?).trim()`.
The combined `?.` operator remains optional chaining on `Option`.

HTTP server accept, body and response operations return `net.NetError`.
`Request.respond`, `respond_text`, `respond_json` and `respond_stream` consume
the request, including on failure. Read the request fields before responding
and remove any later `request.close()` call. Ordinary cleanup releases the
request wrapper. For streaming responses, continue through the returned sink;
close an unanswered request explicitly only when early release is useful.

The pure codec distinguishes incomplete input from invalid input:
`parse_request` returns `Result<Option<Request>, RequestError>` and
`parse_response` returns `Result<Option<Response>, ResponseError>`.
`Ok(None)` means more input is needed, `Ok(Some(value))` contains a validated
message, and `Err` reports malformed or oversized input. Replace request
`reject_status` checks with `RequestError.status()` when choosing an HTTP
rejection response. Remove response `is_valid` and sentinel status checks.
Message builders return `BuildError` for invalid fields or status codes;
propagate or handle it before sending bytes. Codec header accessors return
`Option<string>`.

TLS and WebSocket failures retain protocol and verification details in
`net.NetError`. QUIC setup and operations return checked outcomes through their
resource methods; replace duplicate free-function operations and public
last-error queries with those results.

## Generic numeric iterator terminals

Replace `iter.sum_f64` with `iter.sum` and `iter.product_f64` with
`iter.product`. Both functions infer and preserve the iterator's numeric item
type. The same names now cover signed and unsigned integer widths and floating
point. Empty sums and products return typed zero and one respectively. Existing
integer uses keep their arithmetic behaviour.

## Diagnostic JSON consumers

Read human guidance from the diagnostic's `help` array. Related notes now carry
their own `file` and `span`; resolve each span against that file rather than the
primary diagnostic's source. Import-cycle guidance and parser hints use `help`
instead of message-only note entries. Existing diagnostic codes, channels and
structured fixes retain their roles.

## Deferred values

For first-demand initialization, replace an eager value with
`var value = lazy.new(|| initialize());` after importing `std.lazy`. Read it
with `value.value()`. The mutable binding lets the single owner update its cache;
the result type must support `Clone`. Reads return ordinary value copies;
explicitly shared handles keep their normal sharing behaviour.

Initialization now happens on first demand, so review when its I/O, side effects
and errors should occur. An unused initializer never runs, but its captured
resources still receive ordinary cleanup when the lazy owner is dropped.
`close()` releases the owner early.

The initializer can suspend and is consumed once. A returned `Result.Err` is
cached like any other value. An initializer that faults or is cancelled becomes
terminal; later demands fault. Recursive demand also faults. If retry is part
of the application's policy, construct a new lazy owner deliberately.

## Supervisor restart delays

Existing supervisors need no change. To select exponential delay, import
`std.restart` and add this configuration inside the supervisor declaration:

```text
backoff: restart.exponential(initial: 100ms, maximum: 5s);
```

Both arguments are typed durations. `initial` must be positive and `maximum`
must be at least `initial`; invalid policies fail before children start. The
ordinary policy expression is evaluated once per supervisor construction.

Each role starts with `initial`, doubles after repeated crashes and caps at
`maximum`. A replacement that runs without crashing for the supervisor's
existing restart window resets its next delay to `initial`. The interval starts
when the replacement is successfully published; downtime and suspended
construction do not count. Keep the existing intensity setting for the failure
budget. Strategies, stable role references and crash-hook decisions keep their
existing meanings. Omitted `backoff` retains previous behaviour.

## Generic stream consumers

`Stream<T>` satisfies `Iterator<Item = T>`. Existing direct `for` loops continue
to work. Generic iterator functions can now accept streams without a wrapper;
finishing or closing their last pipe sink lets iteration end after buffered
items drain.

## Concurrent pipelines and consuming callbacks

The fixed-`i64` pipeline pilot is replaced by generic iterator adapters.
Replace `PipelineItemI64`, `StageI64`, `SourceI64`, `SinkI64` and
`AdmissionControlI64` plumbing, including `pipeline.from` and `pipeline.run`,
with `pipeline.prefetch(source, capacity: 8)` and
`pipeline.map(source, transform, concurrency: 4)`. Iterate the result to drive
work. Input order is the default; choose `order: .Completion` explicitly when
results may arrive out of order. Capacities and worker counts must be positive.

A source must implement `Iterator` and be sendable. Streams and generators
with sendable captures, frame values and cleanup can compose directly. Each
worker gets its own callback copy, so preserve `clone` when writing its type.
Use the full callback contract
`fn[clone, suspends](consume T) -> U` for a stored pipeline transform; an ordinary
non-suspending function can satisfy the suspension allowance.

A named transform that previously borrowed its input must declare `consume`
to accept the worker's owner. It may still borrow that input when calling a
helper. A lambda passed directly to `pipeline.map` infers the consuming mode;
write `|consume item: T| ...` when you want to state it explicitly. For example:

```hew,no_run
import std.pipeline;

fn forward(consume value: string) -> string {
    value
}

fn main() {
    let values = ["first", "second"];
    for value in pipeline.map(values.into_iter(), forward) {
        println(value);
    }
}
```

Use `fn(T) -> U` for a borrowed callback and `fn(consume T) -> U` for an owned
input. These modes must match at callable boundaries, including nested types;
changing `fn` to `fn[once]` only changes ownership of the callable itself.
Anonymous actor handlers use `actor |consume message: T| { ... }`, matching
named receive parameters.

Keep pipeline lifetime under the consumer: leaving its loop or closing the
adapter drains child cleanup before releasing inputs, buffered results and
source state. Remove custom stop-and-drain plumbing that served only the old
pilot. If retries are needed, define them explicitly in the application.

## Asynchronous C exports

Keep `--export-c SOURCE=SYMBOL` for a synchronous boundary. Select
`--export-c-async SOURCE=SYMBOL` when a native event loop needs to drive the call.
Rebuild the object, generated header and matching runtime archive together.
The selector works with ordinary public monomorphic functions, including
functions whose checked bodies suspend; it adds no Hew callable syntax.

Replace the selected synchronous invocation with this lifecycle:

1. Supply an owned process runtime, a retained `HewWaker` and empty call/error
   slots to `SYMBOL_start`. Successful admission consumes declared consuming
   owner slots. Refused admission consumes no inputs.
2. Keep borrowed owners and mutable slots live until `SYMBOL_poll` reports
   `HEW_CALL_READY`. Wait for wake callbacks between pending polls. Callbacks
   schedule a future host-thread poll and must never resume or release inline.
3. For cancellation, call `SYMBOL_cancel` and continue draining mandatory
   cleanup. Cancellation is idempotent; a terminal success stays successful.
4. Call `SYMBOL_result` once to take the value or owned error, then
   `SYMBOL_release` to clear the call owner. Early or repeated result and release
   of pending work or an untaken result return `HEW_INVALID_STATE`, preserving
   the call owner and result storage. Releasing a null call slot succeeds.

Start, poll, cancel, result and release stay on the owning host thread and must
not overlap or re-enter. Wake/retain/release callbacks must be thread-safe, and
their context and code must survive until the last retained reference drops.
Release returned values separately before runtime shutdown or code unloading.
Combined body and cleanup faults remain available through the existing owned
error API.

For asyncio, cancellation must drain native cleanup before raising
`CancelledError`, including disposal of an owned result that completed just
before cancellation. The [maintained consumer](../../examples/embedding/asyncio_orders.py)
handles this ordering and leaves inputs untouched when cancelled before entry.
Use the [host guide](../../tests/host/README.md#drive-calls-from-an-event-loop)
for the complete build and event-loop example. Async C exports are native-only;
the experimental interface keeps its same-build linkage requirement.
