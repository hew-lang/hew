## The P0: where the authority actually was

`ExternContractTable` was already correct at both direct gates. It simply was
not the **only** authority for the result gate, because the freshness summary
those gates read is built earlier and independently:

* `funcupdate_fn_returns_fresh` is constructed at `lower/mod.rs:3058`, before the
  call-scrutinee provenance and the table exist;
* its coarse leaf policy maps every body-less resolved item to `Fresh` via
  `unwrap_or(true)`, and a declared `extern "C"` fn **is** body-less;
* the strict helper only required the WRAPPER's own map row to be `true`. It
  never established that the row was **derived** without an opaque extern.

So one visible Hew frame was enough:

```hew
extern "C" { fn host_string() -> string; }
fn wrapper() -> string { unsafe { host_string() } }
fn main() -> i64 { println(f"value={wrapper()}"); 0 }
```

`main` bound the result to `__hew_temp_arg` and emitted
`drop _1 ty=string kind=cow_heap(hew_string_drop)`.

## The fix: a separate taint fixpoint, conjoined once

I did **not** make the coarse fixpoint extern-aware. That map is pinned
byte-identical by `return_provenance::tests::coarse_verdict_differential`, and it
has other consumers (destructive funcupdate, reassign) whose question is the
narrower may-alias-a-by-value-parameter one. Changing its verdict to fix a
release gate would have coupled two unrelated proofs.

Instead the mint's fact is now a **conjunction** of two independent facts:

```
extern_aware_fresh_returns[id] = coarse_fresh[id] && !launders_opaque_extern.contains(id)
```

built once in `build_call_scrutinee_provenance`
(`hew-mir/src/return_provenance.rs`), carried on `CallScrutineeProvenance`, and
read by `callee_returns_analyzed_fresh_owner`
(`hew-mir/src/lower/facts.rs`), whose signature is unchanged — one map in, one
answer out. The coarse map is **passed in** from the single construction site
rather than recomputed, so the pipeline still runs one coarse fixpoint.

### The veto: `compute_fn_return_launders_opaque_extern`

A monotone least-fixpoint from the **empty** set over the same shared
return-alias walk (`return_alias_bits_in_block`), under a new
`OpaqueExternTaintPolicy`. Its bits mean "tainted by an opaque extern", not
"aliases a parameter", so its four clauses read differently from `CoarsePolicy`:

| clause | callee shape | verdict |
| --- | --- | --- |
| 1 | non-item callee (closure, fn-pointer param, dynamic dispatch) | `Opaque` |
| 2 | **declared extern**, claimed by NAME *and* declaration id, ahead of every id lookup | `Fresh` only with an audited fresh-`+1`-return row; `Opaque` otherwise |
| 3 | analyzed module body | `Opaque` if already tainted, else `ParamSubst` |
| 4 | body-less **non**-extern item | `Fresh` via `bodyless_item_is_audited_owned_return` |

### Why it is transitive

Clause 3 reads the callee's row **out of the set being built**, so the fixpoint
closes over call chains rather than inspecting one frame:

* **wrapper of a wrapper** — `wrapper` is tainted on pass 1 by clause 2;
  `wrapper2`'s call to it is then `Opaque` on pass 2. This is the case my first
  attempt got wrong: returning `ParamSubst` for a non-fresh analyzed callee is
  unsound, because `ParamSubst` unions the callee's ARGUMENT bits, and a
  **zero-argument** call unions to `EMPTY` — which reads as fresh. A tainted
  callee must be `Opaque` outright.
* **generic wrapper** — the fixpoint runs over `origin_fns`, i.e. every
  `HirItem::Function` including generic origins, and a monomorphisation's callee
  resolves to the generic origin `ItemId`. The origin carries the taint.
* **recursive wrapper** — taint is injected by non-recursive transfers and
  propagated by union from the empty set, so a cycle touching an extern anywhere
  taints every member, while a clean cycle stays clean.
* **argument laundering** — a still-clean analyzed callee is `ParamSubst`, which
  keeps walking its arguments, so `forward(unsafe { ext() })` is tainted through
  the argument even though `forward` itself is clean.

### Why `leaf_bits = EMPTY` is not a hole

A literal, a binding, an index is not an extern result, so a non-`Call` leaf
contributes nothing. That is sound **because this summary is only ever read as a
veto on top of the coarse proof**, and the coarse proof already fails closed
(`OPAQUE`) on every leaf its own walk reaches. A path the coarse proof admits
therefore consists exclusively of the structural arms and `Call`s this walk
classifies — the two walks visit the same nodes. The `let`-see-through in the
shared walk is policy-independent, so `let v = ext(); v` is caught.

### The audited set was not widened

Clause 4 exists only so the compiler's OWN body-less items keep working —
aggregate constructors, the minted `string_concat` shim an f-string tail lowers
to, the runtime primitives behind `RecordCloneCall`/`Index`/`Slice`. This is
load-bearing: `f"tok{i}"` lowers to a `Call` to `string_concat` with a synthetic
`ItemId` absent from `origin_fns`, so a strict clause 4 would have killed the
very mints this branch exists to create.

An extern can **never** reach clause 4: clause 2 claims every extern by name and
by declaration id first, both answered from the same table, imports included.
`bodyless_item_is_audited_owned_return` asserts exactly that and says in its own
doc that widening it — or widening the table's audited fresh-return set so an
extern reaches clause 2's clean arm — reopens the laundering. `ExternContractTable`
contents are unchanged: `extern_return_is_audited_fresh_owner` still holds only
scalar-return externs (vacuously safe: no heap handle at all), and
`extern_borrows_audited_heap_args` is still unconditionally **empty**.

## The companion fix: `lower/expr.rs`'s dispatch-set check

The synthetic temp-arg mint in `lower_direct_call` still answered a string
argument's ownership question from `module_fn_names`. That set is the call
**dispatch** set and deliberately carries every declared extern so an extern call
lowers as a `Terminator::Call`, so a temporary passed to an extern was registered
as caller-owned purely because the extern was dispatchable. It is now routed
through the table via `Builder::callee_is_analyzed_hew_arg_sink`
(`hew-mir/src/lower/ownership.rs`), which consults the audited table **first**,
exactly as the payload gate (`temp_drop.rs::string_call_borrows`) does, and only
then falls back to the Hew-body dispatch test.

**The veto reads the ARGUMENT authority, not the return-side one.** This was a
real error in my first attempt at this layer, caught by the per-shape census. A
`-> ()` extern such as `fn host_sink(s: string)` carries a **vacuous audited
fresh-RETURN row** — `ty_is_scalar_non_heap(Unit)` is true, so the table admits a
return it never makes — while saying nothing whatsoever about whether it retains
or releases the string it is **handed**. `callee_is_ownership_opaque_extern`
therefore answered `false` for it and the veto never fired.
`callee_is_arg_ownership_opaque_extern` reads
`extern_borrows_audited_heap_args` instead, which is the question actually being
asked and is empty today.

The verdict's scope note holds: this never caused a second drop, because final
string ownership rechecks the terminator through the table and excludes the
escaping argument. It is fixed because a *preliminary* ownership answer must come
from the one authority too.

`lower/expr.rs` sits **exactly** at its 10 000-line ceiling, so this change is
net-zero there: the rationale lives on the helper in `lower/ownership.rs` and the
call site keeps a one-line pointer to it. No ceiling was raised.

## The rewritten strictness test

`analyzed_freshness_strictness`'s positive case did
`HashMap::from([(ItemId(7), true)])` and then asserted the strict helper reported
fresh. That is why this module did not catch the laundering: **the defect was
never the lookup, it was the derivation.** A test that seeds the fact it means to
test proves nothing.

It now uses `freshness_verdicts(source, name)`, which lowers real source and runs
the real fixpoints exactly as `lower_module` does, returning
`(coarse verdict, strict verdict)`. Nothing is seeded.

* positive: `fn mk(i: i64) -> string { f"tok{i}" }` — constructed, not asserted
  into existence;
* negatives: direct wrapper, wrapper of a wrapper, generic wrapper, argument
  launderer, recursive wrapper.

A guard asserts the **coarse** summary says fresh, so a case cannot silently pass
by riding on a coarse decline. One case cannot satisfy that guard, and I record
it honestly rather than hiding it: the coarse fixpoint is a least-fixpoint
needing positive proof, so a **self-recursive** producer never reaches `true`
there in the first place (a pure recursive `f"base"` producer reads false too —
pre-existing behaviour, not a regression from this branch). That case therefore
reads both verdicts and asserts both are false, with a comment stating plainly
that the veto is *redundant* for that shape rather than load-bearing, plus a
guard so the test still holds if the coarse verdict ever changes.

The three pre-existing cases (absent row, analyzed-false row, indirect callee)
are unchanged.

### `hew-cli/tests/extern_ownership_double_release_e2e.rs` — the native case

`a_hew_wrapper_around_an_opaque_extern_sees_no_caller_release`.

The existing root-extern fixture can only pin "released exactly once", because a
root `extern "C" -> string` is `ForeignAdopt`: codegen copies the foreign pointer
into a private header-aware buffer and frees it, so the foreign handle never
reaches Hew raw.

A `HeaderAware` extern is **not** copied — the host's pointer is passed straight
through as a runtime string handle. **Disclosed plainly, because it is a
deliberately narrow hook:** that classification is reached through an extern
declared in a module with stdlib provenance, so the fixture builds a two-file
project whose sibling module is named `std`, declares the extern there and wraps
it in one ordinary Hew frame. It is a real, reachable configuration of the
selected ABI, and it is the only one on which a non-adopting foreign result is
observable. The test says so in its own doc comment.

The host mints genuine header-aware handles itself over the pinned 16-byte
`{ magic: u64, rc: u32, _reserved: u32 }` layout, with `rc` biased by 1 000 000
so no release can drive it to zero and free the buffer underneath the probe, and
keeps every pointer, so each compiler release reads as an exact decrement.

| | previous HEAD | new HEAD |
| --- | --- | --- |
| `made` | 8 | 8 |
| `releases` | **8** | **0** |
| `after_host_release` | — | 1 |

`after_host_release` is the counter's own positive control, run last: one real
`hew_string_drop` issued **from the host** must read as exactly one release, so
the zero above is a measurement and not a blind probe.

## Honest limitation of the release counter

`spy_releases` is a **net decrement** counter: it reports
`sum over handles of (rc_at_handout + BIAS − rc_now)`. A hypothetical later
`hew_string_retain` paired with a release would cancel and read as zero. No such
retain occurs in either fixture — the host never retains after handout, and the
programs interpolate and discard — but the counter cannot *prove* that in
general, only observe the net. I am stating it rather than implying the counter
is a full release trace.
