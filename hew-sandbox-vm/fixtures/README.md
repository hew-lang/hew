# Sandbox VM golden fixtures

Each fixture directory contains:

- `main.hew` — the learner-visible Hew source.
- `expected.trace.json` — the deterministic Trace Schema v0 contract,
  generated by `make sandbox-fixtures-record`.
- `bytecode.json` — generated by `make baselines`, unless the fixture is
  an intentional checker-error source.

Neither artifact is hand-edited. `make baselines` refreshes bytecode alone and
needs no Node, so a fixture whose bytecode changed there still has last
recording's trace and the conformance suites will say so; run
`make sandbox-fixtures-record` to bring both back in step.
`make sandbox-fixtures-record` recompiles the source and runs the VM, carrying each fixture's replay configuration (seed,
step budget, virtual clock and host inputs), so a recording
changes only what the VM observed. Review a regenerated golden by its trace
family sequence and its `final_state`; the full equality the conformance suites
assert is the drift detector, not the review.

The fixture catalog is declared in [`manifest.json`](manifest.json) and described
in [`../specs/golden-fixtures-v0.md`](../specs/golden-fixtures-v0.md).

Regenerate compiled fixture bytecode from the repository root:

```sh
make baselines
```

Check mode is the CI gate:

```sh
make sandbox-fixtures-check
```

Only intentional checker-error sources have no bytecode. Filesystem access
compiles to a package and is refused by VM admission before execution. Every
executable fixture is generated from its source; there are no hand-authored
actor or scheduler packages.
