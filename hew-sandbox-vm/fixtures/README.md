# Sandbox VM golden fixtures

Each fixture directory contains:

- `main.hew` — the learner-visible Hew source.
- `expected.trace.json` — the deterministic Trace Schema v0 contract,
  generated by `make sandbox-fixtures-record`.
- `bytecode.json` — recorded by `make sandbox-fixtures`, unless the fixture is
  an intentional checker-error source.

Recorded packages are compatibility inputs for the public v1 wire format. Keep
valid older packages when compiler internals change. The VM suite executes both
recorded packages and freshly compiled sources against the same observable trace:
event kinds, stdout, exit code, diagnostics, runtime failures and sandbox rejections.
Generated names, block layout and internal VM bookkeeping are not golden contracts.

Neither artefact is hand-edited. Use `make sandbox-fixtures` to deliberately
refresh recorded bytecode, or `make sandbox-fixtures-record` to regenerate both
bytecode and traces. Recording preserves each fixture's replay configuration
(seed, step budget, virtual clock and host inputs). Review changes to observable
behaviour before accepting a new trace.

The fixture catalog is declared in [`manifest.json`](manifest.json) and described
in [`../specs/golden-fixtures-v0.md`](../specs/golden-fixtures-v0.md).

Deliberately regenerate recorded fixture bytecode from the repository root:

```sh
make sandbox-fixtures
```

Check mode verifies that runnable fixture sources still compile and recorded
packages contain valid JSON. Schema validation, wire compatibility and execution
are checked by the VM suite:

```sh
make sandbox-fixtures-check
```

Only intentional checker-error sources have no bytecode. Filesystem access
compiles to a package and is refused by VM admission before execution. Every
executable fixture is generated from its source; there are no hand-authored
actor or scheduler packages.

