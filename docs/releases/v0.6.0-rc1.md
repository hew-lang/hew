# Hew v0.6.0-rc1

Hew v0.6.0-rc1 is the first release candidate for v0.6.0. It is not the final
v0.6.0 release; it is the first public checkpoint for the ownership, runtime,
language, and tooling changes planned for the v0.6 line.

## Ownership and runtime safety

- **Ownership follows one unconditional, type-directed drop model.** The
  release drops owned fields exactly once across composite values, match
  bindings, tuple chains, and temporary arguments. The ownership/drop
  regression corpus, runtime cleanup tests, and checked-MIR verification gate
  cover the model.
- **Resources close through fields.** `#[resource]` fields embedded in records
  now close on scope exit. The resource cleanup tests cover the field-wise
  path, including nested aggregates.
- **Distributed identity is authenticated.** Stable credentials derive node
  identity, route slots pin peer credentials, and durable actor locations fence
  stale sessions. The runtime handshake, routing, monitor, and connection
  teardown tests cover rejection and cleanup paths.

## Language and diagnostics

- **Fallible numeric conversion is explicit.** `try_to_*` conversions reject
  lossy and out-of-range values instead of truncating them. Conversion tests
  cover exact, boundary, and rejected values.
- **Actor dispatch keeps named local handlers and typed remote sends distinct.**
  Local fire-and-forget dispatch remains `ref.method(args)`, using the declared
  `receive fn` name. `.send(args)` on a `LocalPid` is therefore only a local
  dispatch to an actor handler literally named `send`; it is not a replacement
  spelling for every local send. `RemotePid<T>.send(message)` remains the
  remote fire-and-forget surface, and lambda-actor handles retain `.send`.
- **Wire declarations use `#[wire]`.** The declaration surface is aligned with
  the wire codec, with parser, checker, and codec tests covering accepted and
  rejected forms.
- **Iterator coverage is complete across standard collections.** Non-consuming
  `Vec<T>::iter()`, `HashMap::into_iter()`, and the related pipeline and
  `for-in` paths are covered by the collection and end-to-end test suites.
- **Stable identity has a standard-library escape.** `std::arena::Arena<T>` is
  a single-owner generational slotmap whose plain-value `Key<T>` handles remain
  stable across unrelated mutations. Stale, cross-arena, and wrong-generation
  keys fail closed; nested owned values and free-slot reuse are covered by the
  runtime and leak oracles.
- **Machine and actor failures are observable.** Machine guards and emits,
  bounded mailbox policies, supervisor escalation, collection bounds failures,
  and broken-pipe sends now take their specified paths. The vertical-slice,
  runtime, and sandbox parity gates exercise these behaviours.
- **The Hew CLI owns the package surface.** `hew` is the only CLI: package
  commands and native-package builds are Hew subcommands, and `hew init`
  creates a manifest-first project without destructively overwriting existing
  files.
- **Suspend frames remain debuggable.** `hew debug` preserves source scopes and
  live locals across coroutine suspend and resume points, so a debugger can
  inspect the handler before and after an `await`.

## Compatibility notes

`impl Drop for T` is rejected. Handle-like types should use `#[resource]` and
an explicit `close(self)` method; ordinary data types continue to receive
automatic field-wise drop. Local fire-and-forget actor dispatch remains
`ref.method(args)`; `.send(args)` on a `LocalPid` only targets a literal
`receive fn send` handler, while `RemotePid<T>.send(message)` remains the
remote surface. `#[wire]` replaces the removed `struct` wire declaration form.
`Arena<T>` owns mutable identity state and is not cloneable; share its `Key<T>`
values instead of forking the store.

The runtime's actor system-message symbols are no longer declarable from Hew
`extern "rt"` blocks. Lifecycle delivery remains runtime-owned through the
actor lifecycle handlers; embedders that need the symbols must use the
non-Hew-facing runtime surface. `HewChildSpec` also has a breaking C ABI
change: a trailing `sys_dispatch` field now follows `message_drop_fn`, and
hand-built specs must include it (or set it to null).

## Candidate limits and staged publication

Publication for this first RC is deliberately staged. The signed tag publishes
the platform assets and checksums first. npm consumers are then published
manually through `.github/workflows/publish-npm-packages.yml`; npm publication
is not inferred from the tag. The release workflow dispatches the playground
build with its purpose-scoped credential and fails closed if the dispatch or
the resulting run fails. `hew.sh`/`hew.run` cutover and the Android rebuild
follow those publication checks. Homebrew intentionally skips `-rc` tags.

The release-gate workflow and repository contracts validate the candidate
before tagging. Downstream publication remains ordered so a failed or missing
arm cannot be mistaken for a completed first-RC rollout.
